CiteRank.com serves a [Model Context Protocol](https://modelcontextprotocol.io) endpoint at
`https://app.citerank.com/api/mcp`, so an AI client can read your visibility data and manage prompts
without you copying numbers between windows.

The dashboard also documents the connection at **Settings → MCP** in the organization's settings
sidebar: the endpoint, snippets for the common clients, and the tools it registers.

There are two ways to connect. Signing in from the client is the quickest, and the connection then
acts as you, in the workspaces you belong to. An API key is for a client that can't open a browser,
such as a container or a scheduled job, and is also how you grant a client *less* than your own access.

## Quick Setup

[`add-mcp`](https://github.com/neon-solutions/add-mcp) finds the AI clients installed on your machine and
adds CiteRank.com to each of them:

```bash
npx add-mcp https://app.citerank.com/api/mcp --name citerank
```

Add `-g` to install it for every project rather than just the current one, and `-y` to skip the
prompt. Each client then asks you to sign in the first time it uses CiteRank.com. To set up a single client
by hand, or one `add-mcp` doesn't cover, follow its section below.

## Sign In From the Client

Give the client the URL and it opens a browser for you to sign in. There is no application to
register first.

Sign in to CiteRank.com if you aren't already. A **Connect to CiteRank.com** screen then shows the
client's name, the domain that published it (or that it is unverified, when the client named itself),
and the address it sends you back to. Allow the connection with the button that names the client, or
choose **Deny**. When the client runs on your own computer, CiteRank.com can't tell which program is
asking, so allow it only if you just started the connection from a client you trust.

### Claude Code

```bash
claude mcp add --transport http citerank https://app.citerank.com/api/mcp
```

Then run `/mcp` and choose **Authenticate**.

### Claude.ai and Claude Desktop

Custom connectors are available on every Claude plan; the Free plan is limited to one.

1. Open **Customize → Connectors**, choose **+ Add**, then **Add custom connector**.
2. Name it `CiteRank.com`, set the URL to `https://app.citerank.com/api/mcp`, and choose **Continue**.
3. Review the detected authentication settings, choose **Continue**, and choose **Add**.
4. Sign in to CiteRank.com when Claude asks.

On Team and Enterprise plans, an owner adds the connector first under **Organization settings →
Connectors**, choosing **Add**, then **Custom → Web**. Members then find it under **Customize →
Connectors** and choose **Connect**.

### ChatGPT

Custom MCP servers are added from ChatGPT on the web, and workspace admins can restrict them.

1. Open [Plugins](https://chatgpt.com/plugins), choose **+**, then **Add custom MCP server**.
2. Name it `CiteRank.com`, set the server URL to `https://app.citerank.com/api/mcp`, and choose **OAuth** for
   authentication.
3. Confirm the warning with **I understand and want to continue**, then choose **Create as a plugin**.
4. Install the plugin and sign in to CiteRank.com.

### Codex

```bash
codex mcp add citerank --url https://app.citerank.com/api/mcp
codex mcp login citerank
```

### Cursor

[Add to Cursor](cursor://anysphere.cursor-deeplink/mcp/install?name=citerank&config=eyJ1cmwiOiJodHRwczovL2FwcC5jaXRlcmFuay5jb20vYXBpL21jcCJ9)

Or put it in `~/.cursor/mcp.json`, or `.cursor/mcp.json` for a single project:

```json
{
  "mcpServers": {
    "citerank": { "url": "https://app.citerank.com/api/mcp" }
  }
}
```

Cursor shows the server as needing login; sign in from there. Older Cursor releases send a callback
CiteRank.com can't accept, so if signing in fails, use an API key instead.

### VS Code

[Add to VS Code](vscode:mcp/install?%7B%22name%22%3A%22citerank%22%2C%22type%22%3A%22http%22%2C%22url%22%3A%22https%3A%2F%2Fapp.citerank.com%2Fapi%2Fmcp%22%7D)

Or from a terminal:

```bash
code --add-mcp '{"name":"citerank","type":"http","url":"https://app.citerank.com/api/mcp"}'
```

Or run **MCP: Add Server** from the Command Palette, choose **HTTP**, and enter the URL. Or put it
under `servers` in `mcp.json`:

```json
{
  "servers": {
    "citerank": { "type": "http", "url": "https://app.citerank.com/api/mcp" }
  }
}
```

VS Code asks you to sign in the first time it starts the server.

### Devin Desktop

Devin Desktop, formerly Windsurf, shares its MCP servers with Devin CLI:

```bash
devin mcp add -s user citerank https://app.citerank.com/api/mcp
devin mcp login citerank
```

Or put it in `~/.config/devin/mcp_config.json`:

```json
{
  "mcpServers": {
    "citerank": { "url": "https://app.citerank.com/api/mcp" }
  }
}
```

### Antigravity

Antigravity's IDE and CLI, which replaced Gemini CLI, read `~/.gemini/config/mcp_config.json`:

```json
{
  "mcpServers": {
    "citerank": { "serverUrl": "https://app.citerank.com/api/mcp" }
  }
}
```

To sign in, open **Agent settings → Customizations** and choose **Authenticate** next to CiteRank.com. After
signing in, Antigravity shows a code in the browser; paste it back into the settings panel and choose
**Submit**.

### OpenCode

In `opencode.json`, or `~/.config/opencode/opencode.json` for every project:

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "citerank": {
      "type": "remote",
      "url": "https://app.citerank.com/api/mcp",
      "enabled": true
    }
  }
}
```

Then `opencode mcp auth citerank`.

### Goose

[Add to Goose](goose://extension?url=https%3A%2F%2Fapp.citerank.com%2Fapi%2Fmcp&type=streamable_http&id=citerank&name=CiteRank.com&description=Read%20your%20AI%20visibility%20data%20and%20manage%20prompts%20in%20CiteRank.com)

Or run `goose configure`, choose **Add Extension → Remote Extension (Streamable HTTP)**, and enter the
URL.

### Other Clients

Any client that supports remote MCP servers over Streamable HTTP with OAuth can connect: give it
`https://app.citerank.com/api/mcp` and sign in when it asks. A client that only runs local servers can
reach CiteRank.com through [`mcp-remote`](https://www.npmjs.com/package/mcp-remote):

```json
{
  "mcpServers": {
    "citerank": {
      "command": "npx",
      "args": ["-y", "mcp-remote", "https://app.citerank.com/api/mcp"]
    }
  }
}
```

## Or Use an API Key

Issue one from **Settings → API Keys** in the organization's settings sidebar. Keys belong to the
organization, so they are not found under a brand. Issue it read-only and optionally narrow it to
selected brands. Copy the key when CiteRank.com shows it, because it is shown only once.

Send it as a bearer token. ChatGPT only connects by signing in; Claude.ai and Claude Desktop take the
key when you add the connector: choose **No sign in** under **Authentication** and add an
`Authorization: Bearer citerank_...` request header. `add-mcp` takes it as a header for every client it configures:

```bash
npx add-mcp https://app.citerank.com/api/mcp --name citerank \
  --header "Authorization: Bearer citerank_..."
```

Claude Code:

```bash
claude mcp add --transport http citerank https://app.citerank.com/api/mcp \
  --header "Authorization: Bearer citerank_..."
```

Codex, which reads the key from the environment rather than the config file:

```bash
codex mcp add citerank --url https://app.citerank.com/api/mcp \
  --bearer-token-env-var CITERANK_API_KEY
```

Cursor, in `~/.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "citerank": {
      "url": "https://app.citerank.com/api/mcp",
      "headers": { "Authorization": "Bearer citerank_..." }
    }
  }
}
```

VS Code, in `mcp.json`:

A connection made with a key reaches only that key's brands, with that key's access, and shares its
limit of 1,000 requests a minute. Revoking the key in **Settings → API Keys** cuts the connection off
immediately.

## Try

> What is the visibility and share of voice for each tagged prompt in CiteRank.com for `<brand>`?

> What are some AEO opportunities for my `<brand>`?

> Give me an example run for my `<description>` prompt.

## What the Tools Return

Most tools take a brand ID, so an assistant starts with `list_brands`. `get_analytics` returns a
brand's visibility, share of voice, per-model breakdown, and citation totals for a time window.
`get_citations` and `get_query_fanout` show the pages the models cited and the searches they ran, and
`list_runs` and `get_run` return the answers behind the numbers.

Analytics tools take the window as `start` and `end` ISO 8601 timestamps, such as
`2026-01-01T00:00:00Z`, and report rates as fractions of 1, not percentages.

`create_prompts` adds up to 100 prompts to a brand in one call, and adds none of them if the batch
would go over your plan's prompt limit. `update_prompt` changes a prompt's text, its tags, or whether
it's tracked, but not its premium models, which spend your organization's paid pairings; change those
in **Settings → Prompts**.

## Scopes

A connection is only offered the tools its scopes allow, so a client is never shown something it
would then be refused:

| Scope | MCP Tool |
| --- | --- |
| *(none)* | `whoami`, `list_models` |
| `read` | `list_brands`, `get_brand`, `list_competitors`, `list_prompts`, `list_prompt_tags`, `get_analytics`, `get_prompt_performance`, `get_citations`, `get_query_fanout`, `get_opportunities`, `list_runs`, `get_run`, `get_billing` |
| `write` | `create_prompts`, `update_prompt` |

A read-write key can create and edit prompts over MCP, but no tool deletes data and no tool changes
billing. Deleting is a [REST API](/docs/api) concern, and no API key can change billing.

A connection you signed in from acts as you and reaches everything you can, so scopes are a property
of a key rather than of the sign-in.
