**An audit of every file in the 12 most-installed answer engine optimization skills on [skills.sh](https://skills.sh), nearly 19,000 lines in all, checked each claim against its source.** The two most-installed skills teach a misordered version of the GEO paper's results. Six present schema markup, usually FAQ schema, as a citation booster without a primary source. Four compute "GEO scores" from weights nobody validated. And none of them reports a brand's visibility as a rate from repeated runs, which is the only way to know whether any of the advice worked.

**Key facts**

| | |
|---|---|
| Skills audited | **12**, by install count on skills.sh, 3 Oct 2026 |
| Installs of the leading AEO skill | **~135,000** (coreyhaines31 `ai-seo`) |
| Skills that misquote the GEO paper's results table | **2**, including the most-installed one |
| Skills that sell FAQ or schema markup as an AI citation lever | **6** |
| Skills that compute a composite "GEO score" | **4** |
| Skills that can retrieve a real AI answer themselves | **2**: one via a paid scraper actor, one via an optional DataForSEO hook |
| Skills that report visibility as a rate across repeated runs | **0**. One describes the method for a human to follow by hand |
| Factual errors per 32-question benchmark run | **2.7–5.0** with the top skills, 4.7 with no skill |

**Key takeaways**

- The category leader is decent. coreyhaines31's `ai-seo` quotes Google's own guidance, splits crawlers by purpose, and tells you to sample answers repeatedly. Its main problems are a wrong results table, a claim that answer engines parse llms.txt, and a claim about Search Console that has been out of date since June 2026.
- The long tail is worse. Below the top few, skills recommend `<meta name="keywords">`, "15 FAQs with schema", an "18-token extraction rule", and parasite SEO, and one labels ByteDance's crawler as Cohere's.
- Almost everything that is wrong traces back to unsourced statistics: vendor correlations presented as causal weights, or numbers with no traceable source at all.
- The research points somewhere else. Being retrieved matters more than rewriting, third-party coverage matters more than markup, and visibility can only be measured as a rate across many runs.
- In a 32-question benchmark, four of the five popular skills tested scored at or below no skill at all.
- A better skill would keep the good parts, drop the myths, and add a measurement loop, an access audit that runs, and an evidence file with a primary source for every claim.

## What a skill is, and why AEO skills spread so fast

A [skill](https://agentskills.io/specification) is a folder with a `SKILL.md` file: a description that tells the agent when to load it, instructions, and optional reference files and scripts. Claude Code, Cursor, Codex, Gemini CLI, and most other coding agents read the format, and skills.sh ranks public skills by how many times they've been installed.

AEO is a natural fit. The work combines technical checks an agent can run (robots.txt, rendering, indexing), research it can do (what's being cited, by whom), and writing it can draft. That is why the leading AEO skill has around 135,000 installs. Whatever these skills say becomes what thousands of agents tell their users about AI search, which makes their claims worth checking.

## How the Audit Worked

On 3 October 2026, install counts came from the skills.sh search API for the queries "aeo", "geo", "ai seo", "ai visibility", and "answer engine optimization". The audit took the 12 most-installed skills that are actually about AI search visibility, cloned each repository, and read every `SKILL.md` and reference file. Each factual claim was checked against its primary source: the paper, the platform documentation, or the original study. Where a skill cited a statistic with no source, the audit looked for one.

CiteRank.com sells an AI visibility tracker, so weigh these conclusions accordingly. Every claim below links to something you can check.

## What they get wrong

### The GEO paper, misquoted

Nearly every AEO guide cites [GEO: Generative Engine Optimization](https://arxiv.org/abs/2311.09735) (Aggarwal et al., KDD 2024). The two most-installed skills reproduce the same results table: cite sources +40%, statistics +37%, quotations +30%, authoritative tone +25%. The paper's own results put **adding quotations first** (the paper reports its best methods improved its word-share metric by 41%), then statistics, fluency, and citing sources. Authoritative tone sits near the bottom, with a gain of roughly 11–13%.

The order matters less than the context the table drops. The paper measured how much of the answer's text came from a page, in a simulated engine: GPT-3.5 summarizing five fixed Google results. The gains went mostly to pages ranked fifth, at the expense of pages ranked first. When [C-SEO Bench](https://arxiv.org/abs/2506.11097) (NeurIPS 2025) tested the same kinds of rewrites on current models, only 3 of 54 cases showed a significant improvement, and moving a page to the top of the retrieved results beat every rewrite. The coreyhaines31 skill's own evals assert the misquoted figures, so the error is checked into its tests.

### FAQ schema as a citation lever

Six of the twelve present structured data, usually FAQPage, as something that gets you cited: "+40% AI visibility", "highest AI citation rate", "Critical", "15 FAQs with Schema". The audit found no primary source for any of these figures. Google [restricted FAQ rich results](https://developers.google.com/search/blog/2023/08/howto-faq-changes) in 2023 and [stopped showing them](https://developers.google.com/search/docs/appearance/structured-data/faqpage) altogether in May 2026, and its [AI optimization guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide) says AI Overviews and AI Mode need no special schema. A difference-in-differences study of 1,885 pages that added schema found [no lift in AI citations](https://ahrefs.com/blog/schema-ai-citations/), and a small decline in AI Overviews.

### llms.txt as something answer engines read

The leading skill says AI engines "parse `llms.txt`", and one suite has a whole skill for generating it. Ahrefs looked at server logs for 137,000 domains and found that [97% of llms.txt files got zero requests](https://ahrefs.com/blog/llmstxt-study/) in a month, and that AI bots never asked for the file on sites that didn't have one. It is useful for developer documentation, because coding agents read it. It isn't an AEO lever.

### Scores nobody validated

Four skills output a composite score: "GEO Readiness Score: 72/100", a 1–10 "GEO score", "GEO Score v2". Each is a weighted sum of heuristics (citability 25%, schema 20%, brand 20%, and so on) with no validation against which pages actually get cited. The "monitoring" in these skills re-runs the same heuristic, so the score goes up when you do what the score asks for, whether or not any engine noticed.

### Crawler facts that do damage

Crawler mistakes are the most expensive, because a wrong robots.txt rule silently removes a site from an engine. The audit turned up the retired `anthropic-ai` user agent listed as current while `OAI-SearchBot`, the crawler that [decides whether a site appears in ChatGPT search](https://developers.openai.com/api/docs/bots), went unmentioned; `Google-Extended` described as affecting AI Overviews (it controls Gemini training and Gemini app grounding, and [doesn't affect Search](https://developers.google.com/search/docs/crawling-indexing/google-common-crawlers)); training and search crawlers lumped into one list; and ByteDance's crawler attributed to Cohere.

### Measurement left as an exercise

This is the gap that matters most. AI answers change on almost every run: SparkToro found the same brand list [less than once in 100 runs](https://sparktoro.com/blog/new-research-ais-are-highly-inconsistent-when-recommending-brands-or-products-marketers-should-take-care-when-tracking-ai-visibility/), while the share of runs naming a given brand was fairly stable. So the only honest measure is a rate across repeated runs, per engine, against a fixed set of competitors.

The best of the incumbents say so, then leave it to the human ("run each query 3–5 times per platform") or point to a third-party tool. The rest skip measurement entirely, or "monitor" their own audit score. Without measurement, an agent can't tell whether its last recommendation worked, so it can't learn which of its advice to drop.

## What a Better AEO Skill Would Do

The incumbents already get some things right: Google's guidance up front and the purpose-by-purpose crawler split in coreyhaines31's skill, AgriciDaniel's rule of deferring to primary sources, the Measured-versus-Estimated labels from aaron-he-zhu, Sanity's short-router structure, and cognitic-labs' treatment of fetched pages as untrusted input. A better skill keeps those and adds the following.

1. **A workflow with a measurement loop.** Scope, prompt set, baseline, diagnosis, access, owned content, off-site work, then re-measurement against a dated change log. The skill shouldn't make a recommendation without a way to check it.
2. **Prompt sets built from demand.** Prompts come from Search Console queries, sales and support language, community threads, and engines' own fan-out queries, tagged by intent and weighted toward unbranded prompts, which is where brands win or lose.
3. **Statistics an agent can apply.** Runs per prompt for exploratory versus confirmatory claims, and a margin-of-error table, so "down 8 points on 20 runs" gets reported as what it is: no detectable change.
4. **Off-site work driven by the brand's own citation data.** The skill ranks the third-party pages engines actually cite for the prompts the brand loses, with a playbook for each source type and clear lines it won't cross.
5. **An access audit that runs.** It evaluates robots.txt for each AI crawler with RFC 9309 matching, fetches each page as each crawler to catch firewall blocks robots.txt doesn't show, flags noindex and nosnippet, and checks whether content is in the raw HTML that non-rendering AI crawlers see.
6. **Receipts.** The dated facts live in one evidence file with a credibility rating and a primary source for each, plus a myths table, so the main instructions don't go stale and every number can be traced.
7. **The rules that carry legal or policy risk.** The FTC's rule on consumer reviews, disclosure for employees and paid placements, Google's link spam and scaled-content policies, the extra bar for health and finance pages, and the ban on networks of sites posing as independent sources in [Anthropic's Usage Policy](https://www.anthropic.com/legal/aup). When asked for any of it, the skill declines and offers the earned version. It also covers newer ground: product feeds and AI shopping results, pages AI agents have to use, and domain moves.
8. **A short main file.** References load only when the agent reaches the step that needs them.

## How the Skills Compare in Practice

Reading the skills tells you what they claim. A benchmark tested what they do to an agent's answers. It used 32 evals designed to be neutral. No question mentions a tracking product or needs one, and they cover the work the skills are built for, including rewriting a page, fixing JSON-LD, local and ecommerce listings, hreflang, YouTube, rebrands, and review policy. Each comes with fixture files where it needs them (HTML, robots.txt, a CSV of tracked answers) and a rubric of 4–8 checks. Each check is either a fact with a primary source or a judgement call with a stated reason, and a separate review pass loosened any check that favored one school of thought.

Claude Sonnet answered all 32 with each skill installed, and with none, three times each. Claude Opus graded every answer against the rubric without knowing which skill produced it.

| Skill | Checks passed | Facts right | Quality (1–5) | Factual errors per run |
|---|---|---|---|---|
| AgriciDaniel `seo-geo` | 95.2% | 92.1% | 4.53 | 2.7 |
| No skill | 94.5% | 90.6% | 4.38 | 4.7 |
| Sanity `seo-aeo-best-practices` | 94.4% | 91.2% | 4.53 | 3.7 |
| `bencium-aeo` | 94.0% | 90.6% | 4.53 | 3.7 |
| resciencelab `seo-geo` | 93.2% | 89.1% | 4.50 | 4.0 |
| coreyhaines31 `ai-seo` | 93.0% | 90.0% | 4.49 | 5.0 |

The judgement checks barely separate anyone: Sonnet already gives sensible advice, and every setup passed 97–99% of them. The difference is in the facts. Without help, the model often says FAQ rich results still show for health and government sites, that snippet controls are the only way out of AI Overviews, that Search Console has no AI report, and that a canonical tag fixes syndicated copies. A skill can only help by correcting facts like these, and most of the popular ones don't.

Four of the five skills scored at or below no skill. For Sanity's and bencium's, the gap is within run-to-run noise: they repeat the model's stale facts without adding new mistakes. resciencelab's and coreyhaines31's land below no skill on every run, because they add errors the model then repeats: no AI reporting in Search Console, answer engines parsing llms.txt, unsourced percentages, and product markup filled with values the page doesn't state. General-purpose checklists also pull answers away from the question asked, so specifics like testing a page with the accessibility tree or treating "near me" results as location-dependent get dropped.

Keep in mind that Claude graded Claude.

## Measuring the Results With an AI Assistant

An agent can read those measurements itself. CiteRank.com serves an [MCP server](/docs/api/mcp) at `https://app.citerank.com/api/mcp`, so Claude Code, Cursor, Codex, or another MCP client can query a brand's tracked answers alongside whichever skill it uses, or none. In Claude Code:

```bash
claude mcp add --transport http citerank https://app.citerank.com/api/mcp
```

Then run `/mcp` and choose **Authenticate**. Each step of the measurement loop maps to a tool call:

1. **Baseline.** `list_brands` returns the brand id the other tools take. `get_analytics` returns visibility and its daily trend, share of voice against tracked competitors, and a per-model breakdown for any window you give it, with rates as fractions of 1.
2. **Diagnose.** `get_prompt_performance` shows which prompts surface the brand and which don't. `get_citations` lists the pages the models cited, by domain and URL, each marked as the brand's own, a competitor's, or editorial. `get_query_fanout` returns the searches the models ran before answering, for the apps that reveal them.
3. **Read the answers.** `list_runs` lists the answers recorded for a prompt, and `get_run` returns one in full, with every page it cited, so the agent can see how a model describes the brand, not just whether it names it.
4. **Plan.** `get_opportunities` returns the latest opportunities report: what to write, what to fix, and the risks found.
5. **Re-measure.** Tag the prompts a change targets, then call `get_analytics` for equal windows before and after, filtered to that tag. Compare the daily trends, because the headline visibility figure reflects each prompt's latest answers, not the whole window.

Sample size still limits what a comparison can show. On the Basic, Pro, and Business plans, each prompt is checked on each chosen app up to four times a day, so a two-week window holds up to 56 answers per prompt per app. Even then, one prompt's mention rate has a 95% margin of error of up to about 13 points, so judge a change on a tagged group of prompts, not on one.

Signing in gives the agent your own access. To give it less, issue a read-only API key limited to selected brands; tagging prompts with `update_prompt` needs a read-write key. No tool deletes data or changes billing.
